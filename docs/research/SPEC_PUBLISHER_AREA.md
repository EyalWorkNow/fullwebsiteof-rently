# אפיון: האזור האישי למפרסם דירה (עזרא + דשבורד אנליטי)

מבוסס על שלושה מחקרים: מיפוי הדשבורד והנתונים באפליקציה, מיפוי עזרא + ממשק אתי,
ומחקר UX חיצוני על מה שבעלי דירות ומתווכים באמת צריכים.

---

## 0. עקרונות מנחים (מהמחקר, לא מהבטן)

1. **אין מונים מתקתקים בזמן אמת.** אין שום עדות שמספר שמתעדכן חי משנה התנהגות, ויש עדות
   חזקה שהוא מייצר חוסר עקביות ("ראיתי 41, עכשיו 39") ששוחק אמון. זמן אמת שמור ל**אירוע
   בדיד שאפשר לפעול עליו** — פנייה חדשה, התאמה חדשה.
2. **מספר בלי השוואה אינו מידע.** כל מדד מוצג עם משווה: מול דירות דומות באזור, מול עצמו
   בעבר, או מול יעד — ועם מצב איכותי (טוב/סביר/דורש טיפול).
3. **אין אחוזים על מדגם קטן.** מתחת ל־30 במכנה מציגים ספירה גולמית ("3 פניות מ־12 צפיות"),
   לא "8.3%". אחוז על 12 צפיות הוא דיוק מזויף.
4. **משפט לפני גרף.** קהל היעד לא יבנה גרף לעולם. מובילים בהסבר בעברית, ספארקליין קטן
   בשורה, וגרף רק בצלילה פנימה.
5. **כל מדד חייב מנוף.** אם אי אפשר לנקוב בפעולה שהמדד מוביל אליה — הוא לא נכנס.
6. **פילוח קהל מצרפי בלבד, עם סף k≥5.** בלי זהויות, ובלי חיתוך לפי מאפיינים מוגנים
   (דת, מוצא, גיל, הכנסה) — בהתאם לעמדה שהשרת עצמו נקט.
7. **לא ממציאים נתון.** מדד שאין לו מקור אמיתי לא מוצג, גם אם הוא היה נראה טוב.

## 1. מה נבנה — ומה במפורש לא

### נבנה
- אזור אישי למפרסם: `/publisher` (בעל דירה + מתווך, אותו מסך עם דגשים שונים)
- **עזרא** בממשק המלא של אתי — שיחות מרובות, סרגל צד, טיוטה חיה, פרסום
- **דשבורד אנליטי** בשפת העיצוב של האפליקציה, עם:
  - כרטיס בריאות לכל דירה (צפיות, שמירות, פניות — עם משווה אזורי)
  - **פילוח קהל מצרפי** — מי באמת מתעניין, מול מי שהוגדר כקהל היעד
  - מיצוב מחיר מול האזור (מ־priceBadge שכבר קיים)
  - ימים בשוק מול חציון
  - כרטיסי פעולה מומלצת (רק כשיש מנוף אמיתי)
  - עדכון חי **רק** לפניות/התאמות חדשות

### לא נבנה — ולמה
| מה | למה לא |
|---|---|
| ביצועי בוסט | `boostedUntil`/`boostTier` נכתבים ואף פעם לא נקראים בשרת. אין מה למדוד. |
| מדדים מ־`marketSignals` | אפס אזכורים בכל צד השרת. נתון שהלקוח כתב על עצמו. |
| ‏`viewCount`/`likeCount` מהשורה | שבורים מבנית: צפייה חוזרת דורסת את השורה אבל מקדמת את המונה. משתמשים ב־`/count`. |
| מונה צפיות חי | נכשל במבחן "אז מה", ושוחק אמון. |
| פילוח לפי דת/מוצא/גיל/הכנסה | חשיפה לאפליה בדיור. השרת הסיר את זה במכוון; הולכים לפי עמדתו. |
| נתוני התנהגות פרטניים | ‏`/interactions` חושף שהייה/גלילה per-user. מציגים רק מצרפי. |

## 2. מקורות נתונים — מה באמת אפשר

| מדד | מקור | הערה |
|---|---|---|
| צפיות | `GET /property_views/count?propertyId=` | הספירה האמיתית, לא שדה המונה |
| שמירות/לייקים | `GET /property_likes/count?propertyId=` | ⇐ אות כוונה חזק יותר מצפייה |
| פניות | `GET /matches?landlordUid=` | owner-scoped ואכוף |
| הנכסים שלי | `GET /properties?ownerUserId=<uid>` | owner-scoped, IDOR-gated |
| מיצוב מחיר | `GET /listing/enrichment?listingId=` | `priceBadge` — כבר בשימוש בדף הנכס |
| ציון שכונה | אותו endpoint | `neighborhoodScore` |
| ימים בשוק | `createdAt` על השורה | קיים ב־136/136 |
| קהל שהתעניין | `GET /property_likes?propertyId=` + snapshot | פילוח מצרפי בלבד, k≥5 |
| קהל יעד שהוצהר | שדות הקוהורט על הנכס | סוגר את הלולאה |
| בנצ'מרק אזורי | חישוב מקומי מקטלוג הדירות | חציון עיר/שכונה |

**מגבלת ביצועים ידועה:** ה־GSI על צפיות/לייקים הוא HASH בלבד בלי מפתח מיון, כך שחלוקה
לפי ימים קוראת את כל המחיצה. סביר לעשרות־מאות רשומות; לא לאלפים. לכן: מגמה יומית
מחושבת בצד הלקוח עם תקרה, ומדווחת ככזו.

## 3. מבנה האזור

```
/publisher                      ← האזור האישי (שער פעולה, לא חומה)
  ├─ סקירה        Overview      ← תמונת מצב + פעולות מומלצות
  ├─ עזרא         Ezra          ← ממשק אתי המלא, עם יכולות עזרא
  ├─ הנכסים שלי   Properties    ← רשימה + כרטיס בריאות לכל נכס
  ├─ קהל          Audience      ← פילוח מצרפי + מול קהל היעד שהוצהר
  └─ יומן         Calendar      ← קיים, נשאר
```

**מתווך מול בעל דירה:** אותו מסך. מתווך עם 3+ נכסים מקבל בראש טבלת פורטפוליו עם מיון
לפי "דורש טיפול"; בעל דירה בודדת מקבל את כרטיס הנכס היחיד פרוס. ההבחנה אוטומטית לפי
מספר הנכסים — לא הגדרה ידנית.

## 4. חוזה שכבת הנתונים — `lib/live/analytics.ts`

```ts
export interface ListingHealth {
  property: Property
  views: number | null           // null = לא נטען
  saves: number | null
  inquiries: number | null
  daysOnMarket: number | null
  priceBadge: PriceBadgeData | null
  benchmark: {                    // מול דירות דומות (עיר + טווח חדרים)
    medianViews: number | null
    medianDaysOnMarket: number | null
    sampleSize: number            // < 5 ⇒ לא מציגים השוואה
  }
  state: 'healthy' | 'watch' | 'needs_action'
  reasons: string[]               // עברית, מוכן להצגה
}

export interface AudienceBreakdown {
  total: number
  suppressed: boolean             // true כש-total < K_ANON
  segments: { key: string; label: string; count: number }[]
  declaredTargets: string[]       // מה שהוצהר בפרסום
  matchQuality: 'aligned' | 'partial' | 'mismatch' | 'unknown'
}

export const K_ANON = 5           // סף חשיפת פילוח
export const MIN_RATE_DENOM = 30  // מתחת לזה — ספירה גולמית, לא אחוז
```

## 5. עזרא — הממשק

זהה לחלוטין ל־`app/ati` במבנה: סרגל שיחות עם persistence, בועות, צ'יפים, שורת קלט
צפה, מצב טעינה. ההבדלים:
- **כרטיס טיוטה חי** בתוך השיחה (9 שדות — הגרסה של האתר היא הקנונית; באפליקציה יש
  דריפט בין הצ'אט לגיליון הקול)
- **פרסום** בחוזה המדויק של האפליקציה
- **קול** — Web Speech בעברית + הקראה
- **בלי מתג מהיר/מותאם** (זה של אתי בלבד)
- חשיפת הרעיון: השרת כבר מחזיר `cards` ותמונות שהאפליקציה לא מציגה — נשתמש בהם
